## Changes and ownership

The existing technical-design parameter section owns the method-applicability,
initial-basis, inherited-default and useful-feedback judgment. The implementation
Skill makes it actionable at the actual choice. Working plans preserve it through
handoff and recovery; the Learning Loop carries unanswered questions into actual

between the described work, consumed output and observations at the receiving
entry. The optional Harness policy points to these same rules. No new schema,
stage, permanent role, mandatory tuning study or runtime gate was added.

The project adapter correction is limited to result sources. Training, model
selection, scoring and their recovery-signature functions remain unchanged. The
normal check entry and its tracked test inputs include the new isolated result
tests. The existing capability note identifies the supported behavior and its
remaining adoption point. Updating this support does not itself rerun a candidate,
invalidate historical measurements or authorize a new business action.

## Project-adapter review

Initial review caught two defects in the first patch: retaining all scored pools
in memory and attaching current exposure descriptions to historical results.
The implementation was changed to consume cases incrementally and preserve the
historical account separately.

A second independent review found that matching configuration and epoch metadata
could still attach another run's assessment to the normal training field. A hash
written after that association would only preserve the mistake. It also found
that missing auxiliary training records should not prevent scoring valid retained
orders. The corrected adapter isolates these accounts as unknown; normal training
descriptions contain only directly supported model metadata, when available.
Further independent reproductions exposed the same issue in first-use exposure
accounts and a hidden conflict between consistently changed case sources and
model metadata. Exposure accounts now remain explicitly unverified. A scoring
source/model-metadata conflict preserves the independently supported order metrics
and both source descriptions, while leaving the dependent training interpretation
unknown. Cases from inconsistent scoring sources or a mismatched controlled
derivation still cannot produce a mixed complete result.

The original closure reviewer independently ran all 17 result-source tests after
the corrections and confirmed that every reported blocker was closed. Historical
reuse retains the unknown or conflicting state instead of upgrading it merely
because a report was saved. The efficiency reviewer separately found no required
process simplification or new blocking requirement in the rule changes.
