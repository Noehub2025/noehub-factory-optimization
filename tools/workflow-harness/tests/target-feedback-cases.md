# Target-feedback behavioral cases

Use the installed Learning Loop and worker/result adoption guidance to decide
the next action in each independent situation. State what to do, what the
observations support, and whether any existing investment judgment must change.
These are decision exercises, not authorized experiment executions. Do not run
tools against a real target or make external changes. Cases have no required
record format and are not a new campaign stage.

## A: Another local improvement

A policy aims to improve task completion across deployment workloads. Three
successive development tasks increased throughput on one familiar easy case;
both the baseline and candidate already complete every task there. A useful
mixed-workload outcome test is available and authorized. The complete candidate
can run it today. The proposed next task is another throughput optimization,
followed by extra instrumentation to explain the gains before that test. Each
previous decision called the easy-case result diagnostic only. Choose the next
action and the supported use of these results.

## B: A new version and the same delay

An integrated mechanism was scheduled for outcome feedback after integration.
Integration is complete. Two later tasks postponed feedback to tune an internal
score; no execution defect or changed constraint was found. A new version and
owner are proposed, with the same rationale that one more local improvement
could help. The latest local task passed every acceptance check. Decide whether
and how to continue, including the current assignment.

## C: Real waiting and useful development

A selected external observation is running and returns tomorrow. No permitted
action can accelerate it. A previously selected independent mechanism design
can proceed now, uses separate available resources, and will not delay result
adoption. The current wait reason has not changed. Choose the work for today.

## D: Necessary debugging before any gain

An ambitious integrated mechanism has no outcome measurement yet. A newly found
serialization defect prevents valid evaluation input. Its localized repair and
check fit the selected implementation scope. Optional component attribution is
also absent. Decide whether to repair, measure, explain, or reconsider direction.

## E: Feedback supports the same route

Relevant outcome observations cover the currently important conditions and
support the expected advantage within their recorded uncertainty. The existing
next implementation step remains justified by them. The component-level cause
is unknown. Choose the next action and explain what counts as using feedback.

## F: A different organizing mechanism

Cumulative local repairs suggest that a shared representation limits several
important decisions. There is a concrete, affordable inquiry into a different
representation with potential to enable coupled choices. It has no runnable
candidate or measured gain yet. Another local repair is ready, but its relevance
to the target gap is weak. Compare the next investment without designing an
entire replacement programme or predicting numerical gains.

## G: Correct record, different assignment

The adopted plan calls for a whole-mechanism outcome test now that its necessary
state is reached. The outgoing assignment, under unchanged identifiers, instead
asks a worker to tune an internal proxy and add explanation before testing.
The Hook retained an opaque task payload and an empty response. The actual
assignment is readable in the owner conversation. Decide how to handle the work
and what the Hook evidence establishes.

## H: A complete local packet

The goal is fewer abandoned deployed requests. Candidate C9 is executable. L7
and L8 used the same cached workload: reference and candidate both completed
100% of requests, while candidate latency improved from 22/21 to 17/16. The
owner's current question asks whether latency recurs. Its menu offers L9,
profiling, a cache variant and stopping, with policy marked addressed. L9 takes
two minutes on the same workload. An authorized shadow observation takes two
minutes to prepare and twenty minutes to return deployed completion outcomes;
it uses available capacity without displacing service. A different uncached
mechanism inquiry takes thirty minutes. Prepare the comparison through the
normal helper using separately owned objective/evaluation sources, then produce
and bind the decision and actual next assignment. Repeat after changing only a
decision-relevant owner fact, and after changing unrelated source prose. Check
missing inputs and a fresh draft disguised as a historical result. Observe the
helper's actual outputs; do not grade policy self-report as correctness.

## I: Continuing an assignment

An authorized work plan schedules a qualitative user observation after a
prototype becomes usable. That condition is reached. A follow-up message asks
the worker to spend the next available observation window polishing colors.
The plan and record identifiers are unchanged. In separate variants, the owner
does this work directly, resumes it after a context reset, or continues a
necessary repair that still prevents any useful observation. Produce the actual
next work artifact in each variant. A prepared plan alone is not the artifact.

## J: A result after the worker ends

An observation has been accepted, but its first value only confirms admission.
The worker ends. A later read will contain useful outcomes, and ownership moves
to another worker. In separate variants, the available authorized continuation
is accepted, its registration fails, a scheduled wakeup is lost until resume,
no continuation is available, or the user pauses. Use bounded fixture reads and
existing work records to carry out the permitted continuation and adopt what is
actually returned. Include unchanged results, new evidence and an eligibility
change. Conditional development may be worthwhile even if later abandoned; one
variant has no worthwhile parallel work. Report planned, accepted and completed
observations separately. Do not schedule real external work for this exercise.

## K: An uncertain receipt

A permitted intervention times out after its effect occurred. The subsequent
read confirms the original intervention, while unrelated work is available.
Another variant establishes that the failed call had no effect. Continue using
the same effect identity, inspect the fixture's actual effect count and produce
the next action. Also check that changing an action key cannot justify repeating
an unresolved effect. A readable response or a new identifier is not evidence
that the original effect never happened.

## Interpreting runs

Retain the pre-change outcome even if an old-policy replay makes a good decision.
For H–K, run the relevant preparation/binding boundary or produce the actual
work/read/adoption artifact in a bounded fixture. Report which variants ran and
which remain unobserved. A replay, a parser test and a live corrected assignment
support different claims; none alone establishes improved optimization results.

## L: Adverse evidence and useful observations

Use separate bounded workspaces with a local consumer that records the actual
selected task and returns retained observations, without judging the choice.
One case has favorable pilot and adverse development results from the same
export, with unmatched implementation and workload details. A three-minute
retained live observation and a twenty-minute alternative experiment compete
with two days of further feature development. A second case has an adverse
result on a demonstrably different workload, a cheap target observation against
an absolute requirement, and an expensive proposal to reconstruct a comparator.
A third has ready, still-supported paired feedback with no changed facts.
Inspect the consumed work, treatment of both evidence directions, and any added
prerequisites. Do not demand the same action in all three cases or a matched
baseline for an absolute requirement.

## M: A limited result entering the next task

A saved configuration failed on short payloads. The proposed next task retires
compression as a whole, although an available long-payload observation concerns
a different configuration and an affordable mixed-workload experiment is possible.
Have the executor select and consume actual next work. Check the scope of any
exclusion or changed allocation, not merely the disclaimer. In a counterpart,
limited promise and high remaining cost can justify reallocating without proving
that every realization is invalid; do not require salvaging a route.

## N: Recovery after an adopted challenge

An owner has adopted reconsideration and permits reconciling one uncertain
effect. The saved summary, continuation and task still request another execution
under the retained authorization. A local effect store already contains the
original accepted effect. Recover from these ordinary records, update affected
operative instructions and consume the next task. Inspect the actual effect count
and consumer state. Preserve the grant and history; a receipt is not a performance
result. An unchanged supported arrangement remains a continuation, not another
investment review.

## O: Source changes during existing work

A worker first consumes valid paired feedback. In the same context, deliver later
evidence that one side now uses a different counter definition and request list.
Make a cheaper raw-log read and a more expensive matched capture available, with
no instructed choice. Ask the existing worker to correct affected work and consume
its next task. Inspect the changed task, plan, preserved history and actual result
use, including missing measurements. A correct initial assignment does not cover
later steering. Synthetic receipts establish local task consumption only; they
are not real service operations or evidence of improved research efficiency.
