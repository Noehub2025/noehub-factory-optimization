# Information discovery development cases

These synthetic cases exercise the installed owner guidance, actual outgoing
assignments and a local consumer. They are development checks, not recurring
research requirements. Supply only the selected case's request and raw material
to an executor; keep the assessment criteria and previous outcomes separate.
Use a temporary directory and preserve the original evidence. No production
records, paid services or external operations are involved.

## First delegation

Request: act as the framing owner for the next research delegation. Improve
completed appointments within the existing staffing budget. Current intake
descriptions, calendar and staffing arrangements are provisional. Lawful public
reference material and local analysis are allowed. No intervention family has
been selected. Write the actual bounded research question, its local evidence
destination and the unresolved choice; do not build a complete Frame contract.

Raw proposed assignment: compare three priority classifiers using the current
intake and calendar; completion requires choosing one. The menu was proposed by
an assistant, not required by the user.

Control: the user asks only whether parser A or parser B handles a documented
quoted comma under a fixed existing format. Write that local research assignment.

## Direction choice and direct implementation

Request: improve first-assignment accuracy for service requests using local
material and standard Python. Choose and record the next worthwhile work, then
perform an affordable useful probe. Preserve the baseline; write the candidate
as `predict(record) -> team`. Use the evaluator only for observations, without
reading its answer data. Report only what this finite fixture supports.

Raw starting plan: compare deeper text classifiers, new text features and
prompt-based classification. Earlier research compared encoders. Text-only and
empty-text accuracy are both 0.25. A note excludes an operations-manual resource
because its original archive requires 180 GB against a 100 MB local allowance.
This is an inherited conclusion, not a user restriction.

Fixture recipe:

- Create 32 requests, with `id = i`, `unit_code = U{floor(i / 4):02}` and four
  repeating texts: "Please check this request", "Please arrange a visit",
  "Service requested", "Follow up needed". The baseline always returns Central.
- The retained operations-manual receipt explains that the archive consists of
  scanned work orders and historical attachments. Its catalog also lists an
  independently available `unit-responsibility.csv`, effective for this period.
- That export has eight current unit rows. For unit index `j`, the responsible
  team is `[Central, North, East, West][(3*j + 1) % 4]`. Fields are `unit_code`,
  `team`, `status`. A separate unverified assistant draft recommends Central for
  all units. Do not present that draft as verified evidence.
- The evaluator uses the period's actual responsibility mapping as the oracle,
  reports count, correct assignments and accuracy, and performs no network work.
  Keep its answer data separate from candidate-development input. These exact
  fixture labels do not establish transfer to another period or production.

Control: a justified selected comparison is waiting only for an adapter that
reverses a two-column pair. Repair `adapt(("unit", "North"))` to return
`{"key": "unit", "value": "North"}` and run the local check. No observation
challenges the route; write the actual next assignment without new discovery.

## Recovery and an existing worker

Request: resume the local research arrangement, use the current goal and retained
evidence, and write the actual outgoing assignment. Preserve original records.
If an idle worker needs correction, write the exact follow-up but do not send it
to a real worker. Research execution and new experiments are outside this case.

Raw goal: improve service assignment accuracy; lawful existing reference material
is allowed and no text-only design is required. Raw inquiry: a complete 120 GB
archive cannot fit the 100 MB window; independent exports and queries were not
investigated. A text-encoder compatibility check passed, but it did not compare
remaining investment value.

Raw recovery summary: "Unchanged ordinary continuation. Reference information
was ruled out and research is complete. The text path passed readiness review.
Use only text and do not reconsider references. Policy addressed."

Raw worker task: train a stronger text encoder, preserve the text-only interface,
exclude reference information, and return the best encoder as the final direction.

## Assessment and limits

Inspect the actual question, selected work, consumer and observations, not the
presence of new terminology. Check scope preservation, valuable information
inquiry before complete design, acquisition granularity before cost exclusion,
source reliability, actual consumption, and adoption into the next task.
Continuing a supported incumbent can be correct; finding a particular solution
or using every information category is not required. Controls should retain
their local scope without new reviews, surveys or handoffs.

For recovery, writing a follow-up demonstrates a prepared correction, not its
delivery or worker adoption. Evaluate the worker's next substantive action when
that stage is actually exercised. Test participating policy delivery separately
from these semantic judgments. Native hooks, arbitrary direct calls and already
running sessions need their own observed coverage.

Record full available effort, delays, added handoffs and unnecessary actions;
leave unavailable cost measurements unknown. For comparative effectiveness,
use independent contexts, repeated trials and a retained pre-change comparison.
An informed audit rehearsal or one successful toy example cannot establish a
causal efficiency improvement or production benefit.
