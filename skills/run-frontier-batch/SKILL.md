# Run Frontier Batch

Execute one authorized B packet through two invocations. The acknowledgment phase returns only the immutable acknowledgment and performs no work or spend. The execution phase starts only from the Coordinator-owned execution-start record, then returns artifacts, assigned checks and measurements, recovery, actual spend, and one result packet. Do not decide what the campaign retains, promotes, or claims.

## Validate the assignment

1. Read [worker permissions](../frontier-optimization/references/worker-interfaces.md) and [the batch interface](../frontier-optimization/references/batch-interface.md).
2. Recompute `packet_id`. Resolve the packet's campaign generation and immutable Campaign Cycle, Batch Interface, Worker Interfaces, validators, and exact readiness contracts. Rerun frozen structural preflight and require byte-identical output. For user-authorized spend, require unchanged `AUTHORIZATION_READY`, exact V result, Coordinator adoption artifact with `entry_result: ENTRY_READY`, and byte-identical finding-free frozen adoption validation; recompute every identity and confirm the answer exactly matches the reviewed target. A missing, failed, stale, conditional, mismatched, or post-review repair returns `BLOCKED` with zero work and spend. For spend requiring no user authorization, require direct finding-free `ENTRY_READY`. Resolve later strategic spend to unchanged `REPLAN_READY` and complete learning gates.
3. Repeat path ownership validation before acknowledgment as defense in depth. Worker-forbidden paths restrict this worker only. Execution-frozen inputs restrict every actor only after execution start. Reject a worker write that overlaps a forbidden path, frozen input, or Coordinator output. Reject overlapping Coordinator output paths. Reject a broad frozen directory that contains a worker output, packet preflight, execution-start record, or required lifecycle transition.
4. When `changes_executable_candidate: true`, also read [candidate lifecycle](../frontier-optimization/references/candidate-lifecycle.md). For `direct`, resolve `AUTHORIZATION_READY`, V, and Entry adoption bound to exact packet, preflight, source, scope, spend, and stop boundary. For `module` or `system`, require current immutable design identity, exact concerns and traceability, unchanged `DESIGN_READY`, and external development authority bound to that design and scope. Before first measurement, integration, or incumbent use, resolve unchanged adopted `IMPLEMENTATION_READY`.
5. When B cites W, verify its revision, design identity, Delivery row, required concern identities, traceability identity, and evidence destinations. Reject a stale or incomplete binding before acknowledgment. Never require the whole W file to remain byte-identical and never read current authorization from W. For a `ready` design, read only indexed contract sections and concerns whose `Read when` condition matches this B; do not load `technical-design.md` or unrelated concerns.
6. The current campaign-cycle stage executes simple non-code, direct code, complex non-code W, module or system design and code, human-input, diagnostic, focused-research, and separate Slot H evaluation B records. It permits a shared-W parallel set only when all packets bind the same current revision, paths are exclusive, and W names one integration owner and join check. Return `BLOCKED` for external-action, code-bearing `mixed`, unsafe parallel, closeout, or claim-branch work.
7. Write the assigned acknowledgment before work or spend. Accept only when every acknowledgment row matches the immutable packet. Otherwise preserve a blocked acknowledgment and return `BLOCKED` with zero new work. After an accepted acknowledgment, return control without work or spend and wait for the Coordinator-owned execution-start record.
8. On the execution-phase invocation, run the bound execution-baseline verifier with live comparison. Recompute the execution-start and baseline-snapshot identities. Require the record to bind this packet and accepted acknowledgment, prove only the exact required Coordinator lifecycle transition, contain every recoverable post-transition byte, match every live execution-frozen identity, and say `worker_may_start: yes`. Recheck authority that could have changed after acknowledgment. A missing byte, stale, broadened, or conflicting record returns `BLOCKED` with zero work or spend.
9. Return `BLOCKED` for an incomplete, stale, underfunded, unauthorized, contradictory, or path-conflicting packet. Return `waiting_for_input` only under a complete human-input contract.

## Execute within the packet

Set `started_at` only after the execution-start record and its immutable baseline snapshot pass. Start with the smallest checkpoint. Use only allowed operations, feedback, budget, design contracts, code paths, and artifact paths. Protect the preparation limit and required follow-up reserve. Repeat live baseline verification before final result validation. Halt on any post-start change to an execution-frozen input; do not treat a Coordinator-owned lifecycle edit completed and frozen before execution start as drift.

For W-backed work, use only the selected Delivery row and exact required inputs. Append bounded observations only to assigned Milestones and progress or Decisions and discoveries regions. Do not edit W Purpose, Scope, Design brief, Design map, Human input contracts, Delivery map, Validation, Definition of done, or any concern contract.

For candidate code, verify repository disposition, exact authorized packet or reviewed design, source base, workspace, interface, configuration, dependencies, worker-forbidden paths, execution-frozen inputs, and recovery artifacts. Implement one observable slice, run assigned engineering checks, write the sole manifest form, compute the immutable candidate identity, preserve the source result, and report every changed path. Stop with `materialization_state: materialized-stopped` and exact `implementation_review_state: pending`. Set performance evaluation and integration to `not-authorized`, set `experiment_identity: null` and `results: []`, and put candidate information only in its dedicated fields.

For a Slot H evaluation B, require `work_kind: experiment`, `changes_executable_candidate: false`, one immutable candidate and manifest, unchanged adopted `IMPLEMENTATION_READY`, and a precomputed experiment identity binding the evaluator, data, controls, protocol, environment, budget, campaign generation, and result paths. In post-closeout recovery, also require the packet's frozen finding-free candidate-recovery preflight, recovery V, X, inherited Budget, and candidate identity to match the adopted Entry and implementation review. Do not change candidate bytes, evaluator semantics, comparison controls, or measurement inputs. Run only the assigned measurement and comparison-validity checks, preserve raw results, and report the fixed experiment identity. Do not create E, retain or promote the candidate, or choose the next B.

If implementation exposes a shared-interface or other contract-bearing change, write only a discovery with evidence, affected contract, and consequence. Do not edit the contract. The Coordinator must issue a new W revision, obtain fresh `DESIGN_READY`, and obtain new user authorization for affected development before work resumes.

A design B answers only its named design question. A non-code prototype writes isolated evidence and cannot be measured, integrated, promoted, or relabeled as a candidate. If actual work changes executable code, report the scope deviation and do not bypass the code gates.

For human input, validate that the packet names the exact request, schema, provenance, quality and legality checks, confidentiality handling, response path, accept or reject conditions, and resume event. When no response exists, write the request and return `waiting_for_input`. When it exists, preserve its bytes and metadata, run only assigned checks, and report `received-unvalidated`, `accepted-as-evidence`, or `rejected`. Never turn supplied data into a technical conclusion, E, or user value choice; route an actual preference or authorization through V.

Apply legality, measurement, and comparison checks only when the packet authorizes that phase. Report observed versus expected evidence and decision-relevant surprises without selecting a follow-up. A diagnostic B must run the assigned smallest distinguishing check only; a focused-research B must not expand into a route-landscape refresh unless its packet authorizes that scope.

Write only the assigned acknowledgment, artifacts, permitted W progress or discoveries, candidate manifest when applicable, result-validation artifact, and exactly one result packet. Never write the Coordinator-owned packet preflight, execution-baseline snapshot, or execution-start record. Build the result at a temporary non-authoritative path, run the bound result validator in draft mode, insert only its computed result identity, rerun frozen validation to a temporary path, require byte-identical validation output, and only then atomically place the final bytes at the assigned immutable result path. Account for the execution baseline, every output, check, spend item, deviation, input state, and recovery point. A code recovery point must make the candidate auditable without the live branch or worktree.

Return every simple non-code outcome truthfully: `completed`, `interrupted`, `failed`, `blocked`, or `waiting_for_input`. Use `actual_spend: unknown` when accounting cannot establish an amount; never replace unknown spend with zero. Worker output is evidence only and never creates E or adopts a campaign result.

Do not edit parents, F1-F8, ledger records, indexed design concerns, Coordinator-owned W sections, or review artifacts. Do not change the packet, move budget, integrate or promote a candidate, stop the campaign, or publish a claim.
