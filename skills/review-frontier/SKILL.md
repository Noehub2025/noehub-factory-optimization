# Review Frontier

Resolve one assigned independent question about a saved project subject. Write one R when new judgment is needed; R is not a permission credential or execution identity. Do not repair the subject, research, reselect, ask the user, recommend a Coordinator route, or adopt campaign state.

## Select one review branch

1. Select the current method through the [review branch registry](../frontier-optimization/references/review-branches.md), using the assigned next use and remaining question. Correct an incompatible kind, scope or completion condition with the Coordinator in this task. If applicable conclusions already settle the needed judgment, return those references and their coverage for adoption rather than creating a duplicate R or a new verdict. This does not grant permission or settle an unexamined condition.
2. For needed new judgment, require `review_kind: entry | replan | design | implementation | claims`, one full subject Git commit, explicit repository-relative subject paths, one R handle and output path, applicable parent references, and the question's completion check under [Review input roles and corrections](../frontier-optimization/references/provenance-and-identity.md#review-input-roles-and-corrections).
3. Read the selected saved inputs and triggered supporting material. Return a concrete reference error for correction, retaining applicable work. An unresolved required input blocks only its dependent judgment. Historical inputs establish what happened; current rules govern this work. A later working-copy change does not alter the saved subject.
4. Apply the selected method to the saved project facts. For a correction, inspect the saved diff, changed dependencies, and affected conclusions; do not repeat unaffected work merely because the commit changed.

An installed workflow update never changes the historical subject or verdict. Apply current review rules to the next review without making workflow files, validators, bundle versions, or deployment paths part of the project subject.

Historical review packets, snapshots, content roots, and typed provenance remain readable only when the retained R actually uses them. Do not generate or backfill those fields for current work.

## Preserve review independence

Check source artifacts, not only summaries. Apply [Finding effects](../frontier-optimization/references/finding-effects.md). Cite the affected subject and supporting source content at their saved versions for every block, repair, advisory, and checked positive result. Do not return a positive verdict while a block or repair remains open. Keep advisories separate from readiness, strength, validity, progress, and constraint conclusions. Reuse evidence-backed conclusions for their supported use; a review supplies neither user permission nor an investment decision.

Use [Finding effects](../frontier-optimization/references/finding-effects.md) to distinguish a correction needed for the current use from a defect that may remain unfixed. Explain the consequential impact of a blocking finding and the correction or missing evidence needed; an advisory needs no repair plan or acceptance approval. Accept a sufficient correction without demanding general perfection. If a reviewed gate obstructs the current use, check its basis under [Professional output and workflow decisions](../frontier-optimization/references/worker-interfaces.md#professional-output-and-workflow-decisions), not only fidelity to its wording. Stay within the assigned question rather than auditing all historical rules.

When new judgment is needed, write only the assigned R artifact with:

- R handle and review kind;
- subject Git commit and paths;
- applicable parent handles;
- verdict and checked conclusions;
- findings and advisories;
- reviewer and assumptions;
- maximum supported consequence: actual technical coverage and its limits; and
- recovery condition when nonpositive: the correction or evidence needed to resolve the finding, not a prescribed chain of reviews.

Do not edit the subject, Campaign, Selection, Batch, Budget, V, E, W, or claims. Return established conclusions or the new R for adoption. The Coordinator checks their applicability and continues the covered next action under [Review applicability and adoption](../frontier-optimization/references/batch-current.md#review-applicability-and-adoption); a report's return is not an automatic next review. New judgment is complete when the R answers the assigned question and passes its ordinary completion check. Reuse transfers neither an attestation nor authority.
