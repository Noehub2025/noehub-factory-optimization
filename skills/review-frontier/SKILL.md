# Review Frontier

Audit one Coordinator packet independently. Write one verdict artifact. Preserve the snapshot and findings; do not repair, research, reselect, ask for a different answer, recommend a Coordinator route, or adopt campaign state.

## Select one branch bundle

1. Require `review_kind: entry | replan | design | implementation | claims`, canonical task path, exact parent bindings, one immutable packet and snapshot bundle, one assigned review path, and a completion check.
2. Read [Frontier core](../frontier-optimization/references/frontier-core.md), [worker permissions](../frontier-optimization/references/worker-interfaces.md), and [review snapshots](../frontier-optimization/references/review-snapshots.md).
3. Load exactly one branch bundle:
   - `entry`: [Entry and planning](../frontier-optimization/references/entry-and-planning.md), [Campaign cycle](../frontier-optimization/references/campaign-cycle.md), [Campaign state](../frontier-optimization/references/campaign-state.md), [Planning records](../frontier-optimization/references/planning-records.md), [Batch interface](../frontier-optimization/references/batch-interface.md), and [Entry review](../frontier-optimization/references/entry-review.md). For `authorization-readiness`, require `authorization_state: pending`, validate the proposed target and state transition in full, and return `AUTHORIZATION_READY` only when the exact object is eligible to present. Verify the packet and Entry validators, the planned post-answer adoption validator, W traceability, recovery lineage, acknowledgment, Coordinator lifecycle transition, execution start, and path ownership as one executable contract. Do not require or accept a completed user answer in this snapshot. When any selected or predecessor B is code-bearing, also load [Entry code planning](../frontier-optimization/references/entry-code-planning.md), [Candidate lifecycle](../frontier-optimization/references/candidate-lifecycle.md), and the W/design references cited by the packet.
   - `replan`: [Campaign state](../frontier-optimization/references/campaign-state.md), [Planning records](../frontier-optimization/references/planning-records.md), [Evidence records](../frontier-optimization/references/evidence-records.md), and [Learning loop](../frontier-optimization/references/learning-loop.md). Verify complete terminal-B and E reflection coverage, applicable joins, the smallest sufficient diagnosis, user decisions, the deterministic R8 branch, and the exact proposed F2-F4, Budget, Selection, and B state. Load a specialized design or implementation reference only when the snapshot claims that gate remains current. Do not complete a claim branch from a replan review.
   - `design`: [Planning records](../frontier-optimization/references/planning-records.md), [Work plan](../frontier-optimization/references/work-plan.md), [Technical design](../frontier-optimization/references/technical-design.md), and [Design review](../frontier-optimization/references/design-review.md).
   - `implementation`: [Campaign cycle](../frontier-optimization/references/campaign-cycle.md), [Planning records](../frontier-optimization/references/planning-records.md), [Batch interface](../frontier-optimization/references/batch-interface.md), [Candidate lifecycle](../frontier-optimization/references/candidate-lifecycle.md), and [Implementation review](../frontier-optimization/references/implementation-review.md). For `review_mode: materialization`, use the exact workflow-contract and validator versions bound by B, verify the immutable pre-authorization preflight and its authorization binding, reconstruct every execution-baseline snapshot byte without substituting later live campaign records, and reproduce the frozen result validation byte for byte. Load only the W/design inputs cited by B. For `review_mode: recovery-reuse`, use both the historical contracts for provenance and the current snapshotted recovery contracts for new-generation authority; verify the finding-free frozen candidate-recovery preflight, recovery V, X, inherited Budget, exact unchanged candidate, zero new proposal identity, and planned separate evaluation boundary without revising the old B or verdict. Recompute canonical candidate bytes independently of conversation-supplied digests. Apply the recovery rule when a historical packet predates execution-start or packet-preflight records; do not manufacture one or treat its absence as candidate drift when the required terminal and closeout evidence bounds the old authority defect. For direct materialization, verify the exact packet, preflight, and source-base authorization, recoverable acknowledgment, execution-baseline and execution-start lineage, validated materialization artifacts, and the absence of performance evaluation, integration, or incumbent use.
   - `claims`: [Campaign state](../frontier-optimization/references/campaign-state.md), [Planning records](../frontier-optimization/references/planning-records.md), [Evidence records](../frontier-optimization/references/evidence-records.md), [Claim records](../frontier-optimization/references/claim-records.md), [Learning loop](../frontier-optimization/references/learning-loop.md), and [Claim review](../frontier-optimization/references/claim-review.md). Review every named C and write only the assigned claims-review artifact. Do not write A or X, change `campaign_status`, decide whether the branch returns to Cycle, or produce a closeout handoff.
4. Verify that the packet supplies immutable copies or stable content-addressed identities for every parent Slot, R8 rule, design input, implementation input, measurement, and bound the branch must interpret. Return `BLOCKED` when a required normative source, snapshot input, identity, or path is missing, inconsistent, or mutable during review.

One branch bundle means one review purpose, not one file. Do not load another branch's review method unless the current packet claims that separate verdict as existing authority; in that case, inspect only the immutable verdict and inputs needed to verify its freshness.

## Preserve review independence

Check source artifacts, not only summaries. Cite immutable evidence for every finding and checked positive result. Do not accept a stronger result while any finding remains open. Do not turn a user preference into technical proof or let one review substitute for another gate.

Write only the assigned review artifact. Do not edit campaign records, packets, W, design concerns, code, evidence, parents, or source artifacts. Do not prescribe repairs or the next campaign stage, authorize spend, integrate or promote a candidate, write A, or approve publication. State only the verdict, findings, maximum supported consequence, and conditions a later snapshot must satisfy. The Coordinator applies the recorded-state router and decides what happens next.
